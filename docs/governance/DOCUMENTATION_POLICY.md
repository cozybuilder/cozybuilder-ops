# DOCUMENTATION_POLICY — 문서 분류·소유·수명주기

> 역할: CozyBuilder 문서가 어디에 무엇을 기록해야 하는지 정하는 운영 정책.
> 읽는 시점: 문서 생성·이동·요약·자동수정·대규모 정리 전.
> 기계 검사 기준: [`docs-guard.config.json`](../../docs-guard.config.json).

## 1. 목적

문서는 많이 남기는 것이 아니라, **현재 판단에 필요한 정보가 정확한 한 곳에 있고 과거 근거는
필요할 때 찾을 수 있는 상태**로 관리한다.

- 현재 기준과 과거 이력을 분리한다.
- 같은 사실을 여러 활성 문서에 복제하지 않는다.
- 매 작업의 기본 필독 문서는 작게 유지한다.
- 분류가 불명확하면 임의 위치에 쓰지 않고 소유 문서를 먼저 정한다.
- 활성 기준이 충돌하면 최신 날짜로 임의 선택하지 않고 `KNOWN_CONFLICTS.md`에 등록해 중단한다.

## 2. 문서 유형과 단독 소유 정보

| 유형 | 대표 경로 | 단독 소유 정보 | 읽는 시점 |
|---|---|---|---|
| 헌법 | `GLOBAL.md` | 전 조직 불변 원칙·권한 우선순위·절대 금지선 | 항상 |
| 절차 라우터 | `PLAYBOOK.md` | 공통 시작·종료 흐름과 조건별 절차 링크 | 항상 |
| 프로젝트 등록부 | `PROJECTS.md` | 프로젝트 ID·상태·저장소·기본 브랜치·진입 포인터 | 항상 |
| 제품 기준 | `<repo>/docs/AI_CONTEXT.md` | 사용자·제품 범위·불변식·기술/데이터 기준·프로젝트 금지선 | 파일이 있는 프로젝트 진입 |
| 현재 상태 | `<repo>/docs/STATUS.md` | 현재 단계·진행 중·OPEN/BLOCKED·최신 검증 기준·승인된 다음 작업 | 프로젝트 진입 |
| 도메인 명세 | `<repo>/docs/domains/*.md` | 특정 기능의 현재 동작 | 관련 기능 작업 |
| 결정 기록 | `<repo>/docs/decisions/D-*.md` | 결정·이유·대안·대체 관계 | 관련 결정 확인 |
| 검증 근거 | `<repo>/docs/qa/*` | 테스트·빌드·실기기 검증 상세 | 검수·회귀 |
| 출시 변경 | `<repo>/docs/CHANGELOG.md` | 사용자에게 실제 출시된 변경 | 출시 |
| 릴리스 증거 | `<repo>/docs/releases/*` | 버전·HEAD·해시·배포물·재사용 금지 근거 | 빌드·배포 |
| 과거 기록 | `<repo>/docs/history/*` | 더 이상 현재 기준이 아닌 작업일지·이전 문서 | 과거 조사만 |
| 운영 사고 | `docs/operations/PM_INCIDENTS.md` | 사건 사실·영향·사후 분석 | 동일 유형 사고 |

## 3. `GLOBAL.md` 입장 기준

다음 네 질문에 모두 `예`인 내용만 헌법에 들어간다.

1. 모든 CozyBuilder 프로젝트에 적용되는가?
2. 특정 시점·제품·도구·담당자 상태가 바뀌어도 유지되는가?
3. 위반 시 하위 문서나 실행을 무효로 할 만큼 상위 원칙인가?
4. 절차·전략·역할 상세·현재 상태·사건 기록으로 분류할 수 없는가?

날짜가 붙는 사실, 제품별 정보, 도구 기능·요금, 매출 목표, 역할의 상세 업무, 작업 템플릿,
사고 사례, 단계별 방법은 `GLOBAL.md`에 기록하지 않는다.

## 4. 현재 문서와 이력 문서

### 현재 문서

- 지금 유효한 값만 둔다.
- 과거 완료 내역은 최근 3건 이내의 링크만 허용한다.
- 변경 이유가 필요하면 ADR을 링크한다.
- 상세 검증은 QA·릴리스 기록을 링크한다.

### 이력 문서

- 첫 부분에 `ARCHIVE — 현재 SSOT 아님`을 표시한다.
- 현재 기준 문서를 링크한다.
- 기본 필독 순서와 라우터에서 제외한다.
- 원문 보존이 목적일 때는 요약으로 대체하지 않는다.

## 5. 기본 컨텍스트 예산

기계 기준은 `docs-guard.config.json`이 소유한다.

- `GLOBAL.md + PLAYBOOK.md + PROJECTS.md`: 합계 24 KiB 이하
- `GLOBAL.md`: 8 KiB 이하
- `PLAYBOOK.md`: 8 KiB 이하
- `PROJECTS.md`: 8 KiB 이하
- 신규 프로젝트 `AI_CONTEXT.md`: 16 KiB 이하
- 신규 프로젝트 `STATUS.md`: 12 KiB 이하

초과가 필요하면 내용을 삭제하는 대신 조건부 문서나 이력 문서로 분리하고 링크한다.
기존 프로젝트에 `AI_CONTEXT.md`가 없으면 README와 지정된 STATUS를 진입 정본으로 사용한다.
새 구조로 이전하기 전까지 파일 존재를 추측하거나 빈 문서를 자동 생성하지 않는다.

## 6. 기록 전 분류 게이트

문서를 바꾸기 전에 다음 순서를 지킨다.

1. 기록할 문장을 `원칙 / 절차 / 등록 정보 / 제품 기준 / 현재 상태 / 결정 / 검증 / 출시 / 이력` 중 하나로 분류한다.
2. 위 표에서 단독 소유 문서를 찾는다.
3. 같은 정보가 다른 활성 문서에 있으면 한 곳만 남기고 나머지는 링크로 바꾼다.
4. 소유 문서가 없으면 임시로 `GLOBAL.md`나 `STATUS.md`에 넣지 않는다. 새 유형과 소유권을 먼저 승인한다.
5. `node scripts/verify-docs-guard.mjs`를 실행한다.
6. 완료 보고에 변경 문서·분류 근거·가드 결과·commit·push를 포함한다.

## 7. 무손실 이전

- 대형 현재 문서를 축소하기 전에 기준 commit과 원문 blob을 확인한다.
- 미해결 사항·데이터 보호선·마이그레이션·릴리스 증거·검증 한계는 새 소유 문서로 직접 옮긴다.
- 완료 작업일지와 오래된 검증은 `history/` 또는 `qa/`로 이동한다.
- 원문 삭제가 필요한 경우 Git 이력이나 명시적 archive 경로로 복구 가능해야 한다.
- 새 구조로 대표 질문을 답해 본 뒤 정보 손실이 없을 때만 이전을 완료한다.

## 8. 금지

- `STATUS.md`에 완료 보고를 계속 붙이는 행위
- `AI_CONTEXT.md`에 최신 HEAD·버전·당일 작업 결과를 기록하는 행위
- `CHANGELOG.md`에 미출시 내부 구현을 누적하는 행위
- 동일 결정 전문을 `AI_CONTEXT·STATUS·DECISIONS·CHANGELOG`에 반복하는 행위
- archive를 현재 기준처럼 인용하는 행위
- 분류가 불명확하다는 이유로 `GLOBAL.md`에 임시 저장하는 행위
