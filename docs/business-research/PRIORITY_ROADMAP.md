# PRIORITY ROADMAP — 검증·개발 우선순위

> 사업 아이디어를 감으로 선택하지 않고, 수익성과 실행 가능성을 기준으로 검증·개발 순서를 정한다.

## 평가 원칙

- 높은 점수가 곧 개발 확정을 뜻하지 않는다.
- 근거가 부족한 항목은 높은 점수를 주지 않는다.
- 개발보다 먼저 가장 작은 비용의 검증 단계를 배치한다.
- CozyBuilder의 경험·기존 코드·콘텐츠·고객 접점을 재사용할 수 있는 아이디어를 우선 검토한다.
- 기존 AI나 SaaS로 충분히 해결되는 문제는 차별화 근거가 없으면 후순위로 둔다.

## 평가 기준

각 항목을 1~5점으로 평가한다.

| 기준 | 1점 | 5점 |
|---|---|---|
| 실제 수요 | 근거 없음 | 반복적이고 명확한 지불 수요 확인 |
| 수익 발생 속도 | 장기간 개발 후 가능 | 짧은 검증·판매로 매출 가능 |
| 수익성 | 비용 구조 불리 | 반복 매출·높은 마진 가능 |
| 개발 난이도 | 복잡한 기술·장기 개발 | 기존 기술로 빠른 MVP 가능 |
| 운영 난이도 | 지속적인 수작업 필요 | 자동화·소수 운영 가능 |
| 초기 비용 | 큰 선투자 필요 | 거의 비용 없이 검증 가능 |
| 기존 자산 재사용 | 재사용 불가 | 코드·콘텐츠·경험 적극 재사용 |
| 창업자 적합성 | 경험·접점 없음 | 직접 경험과 강한 문제 이해 |
| 차별화 가능성 | 복제 수준 | 명확한 개선 가치와 진입 장벽 |
| 경쟁 강도 | 대형 경쟁자와 정면 경쟁 | 세분시장 또는 구조적 빈틈 존재 |

## 우선순위 등급

- `P0`: 즉시 검증 — 비용이 작고 수익 가능성이 높음
- `P1`: 다음 검증 — 추가 조사 후 빠르게 실험
- `P2`: 관찰 — 조건이나 자원이 확보되면 검토
- `P3`: 보류 — 현재는 실행 가치가 낮음
- `폐기`: 근거 부족, 수익성 부족, 차별화 불가
