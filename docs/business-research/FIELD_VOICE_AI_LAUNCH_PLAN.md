# 건축·인테리어 현장 음성 AI — 기획부터 유료 배포까지

> 상태: 검증·개발 병행 준비
> 기준일: 2026-07-14
> 원칙: 완벽한 현장관리 시스템을 만들지 않고, 음성파일 1개를 업로드해 바로 가치 있는 결과를 얻는 흐름을 먼저 유료 출시한다.

## 1. 출시 목표

첫 공개 버전부터 다음 흐름을 제공한다.

```text
회원가입
→ 14일 무료체험 시작
→ 현장 생성
→ 회의·협의 음성 업로드
→ 현장용어 기반 전사
→ 결정·담당자·기한·금액·변경·미확정 항목 추출
→ 회의록·확인 메시지 생성
→ 원음 타임스탬프 확인
→ 무료체험 종료 후 구독 전환
```

초기 제품은 법적 책임 판정, 증거능력 보장, 실시간 회의 참여, 전체 현장관리, 자재발주, ERP 연동을 하지 않는다.

## 2. 검증과 개발의 병행 원칙

- 커뮤니티 불편 사례 조사와 음성 기술 실험을 중단하지 않는다.
- 조사 결과가 나올 때까지 개발을 미루지 않는다.
- 첫 MVP는 후보 A·B의 공통분모인 `회의 음성 → 결정·변경·할 일·확인 메시지`로 제한한다.
- 실제 사용 결과를 보고 추가공사, 하자책임 검색, 작업일보 중 우선 기능을 정한다.

## 4. 권장 기술 구조

### 프론트엔드

- Next.js + TypeScript
- 반응형 웹 우선
- PWA는 후속
- 상용 배포는 Vercel Pro 또는 대체 상용 호스팅 사용

### 인증·DB

- Supabase Auth
- Supabase PostgreSQL
- Row Level Security로 사용자별 데이터 분리

### 음성 저장

- Cloudflare R2 비공개 버킷
- 브라우저에서 presigned URL로 직접 업로드
- 앱 서버를 거쳐 대용량 파일을 전달하지 않는다.
- 원음 보존 기간을 요금제별로 제한한다.

### 비동기 처리

```text
업로드 완료
→ processing_job 생성
→ 작업 큐
→ 음성 전사 API
→ 현장용어 교정
→ 구조화 추출
→ 결과 저장
→ 완료 알림
```

긴 음성은 웹 요청 안에서 끝까지 처리하지 않는다. 재시도·중복실행 방지·실패 상태를 포함한 비동기 작업으로 처리한다.

### AI 계층

1. 음성 전사
2. 현장용어 사전·공종·회사 용어를 이용한 교정
3. 구조화 JSON 추출
4. 회의록·확인 메시지 생성
5. 결과와 원음 타임스탬프 연결

AI가 생성한 내용은 `AI 초안`으로 표시하고, 금액·숫자·날짜·승인·부정 표현은 사용자 확인 대상으로 강조한다.

## 5. 현장용어 구조

### 출시 전

- 건축·인테리어·공종별 공개 용어자료 수집
- 표준어·은어·일본식 표현·자재·공구·규격·동의어·발음 변형 정리
- 검색 가능한 기본 지식베이스 구축

### 출시 후

```text
공통 사전
→ 공종 사전
→ 회사 사전
→ 개인 표현
```

AI가 모르는 용어는 담당자가 수정한다. 수정값은 해당 회사에 즉시 적용하고, 여러 회사에서 반복 검증된 표현만 공통 후보로 올린다.

## 6. 결제 전략

### 기본 정책

- 14일 무료체험
- 체험 중 사용량 제한 적용
- 체험 종료 후 결제 성공 시 계속 사용
- 실패 시 읽기·내보내기만 허용하고 신규 분석 차단
- 사용자가 직접 해지 가능

### 국내 결제

- 토스페이먼츠 자동결제를 우선 검토한다.
- 빌링키 발급 후 결제일마다 승인 API를 호출하는 구독 로직과 웹훅 처리가 필요하다.
- 자동결제는 리스크 검토와 추가 계약이 필요하므로 신청은 개발 첫날 진행한다.

### 승인 지연 시

자동결제 계약 때문에 공개가 늦어지지 않게 한다.

1. 14일 체험은 즉시 공개
2. 결제 승인 전에는 베타 이용자에게 수동 결제 또는 별도 결제 링크 제공
3. 승인 완료 후 자동결제로 전환

### 초기 요금제 가설

- 베타 단일 요금제만 운영
- 월 포함 음성 시간 제한
- 초과 사용 차단 또는 추가시간 구매
- 무제한 요금제 금지

가격은 음성 1시간당 실제 전사·LLM·저장 비용을 측정한 뒤 확정한다.

## 10. 개발·배포 순서

### 0. 제품 가설 고정

- 첫 고객: 건축·인테리어 대표·실장·현장소장·공무
- 첫 상황: 현장회의·협의·추가공사 논의
- 첫 결과: 회의록 + 결정·변경·할 일 + 확인 메시지
- 성공지표: 음성 업로드 후 결과를 수정·복사·공유하는가

### 1. 조사·데이터 준비

- 커뮤니티 불편 사례 수집

## 11. 출시 판정

다음이 작동하면 출시한다.

```text
회원가입
+ 14일 체험
+ 음성 업로드
+ 전사
+ 결정·변경·할 일 추출
+ 회의록·확인 메시지
+ 원음 타임스탬프
+ 결과 수정·복사
+ 결제 전환 경로
```

기능이 적어도 이 흐름이 실제 음성으로 작동하면 공개한다. 커뮤니티 조사와 사용자 수정 데이터를 받아 다음 기능을 결정한다.
