# 1인기업 비즈니스 리서치

> 다른 1인기업과 소규모 SaaS가 어떤 아이디어로 돈을 버는지 조사하고, 고객의 불편·반복 작업·시간 낭비를 줄이는 새로운 서비스 아이디어를 발굴해 검증·개발 우선순위를 관리한다.

## 수집 목표

- 상용화되어 실제 결제 흐름이 있는 1인기업·초소형 SaaS **100개**를 수집한다.
- 한 번에 약 10개씩 조사하고 사례 문서에 누적한다.
- 현재 수집: **28 / 100** (2026-07-13)
- 100개 수집 전에는 성급하게 한 분야로 좁히지 않고 아이디어 패턴을 넓게 본다.

## 운영 흐름

1. 실제 결제가 발생하는 1인기업·소규모 서비스를 찾는다.
2. 서비스가 어떤 불편과 반복 작업을 없앴는지 기록한다.
3. 어떤 아이디어로 서비스를 구축했는지 파악한다.
4. `아이디어 구조 → 기존 방식 → 바꾼 방식 → 바로 결제하는 이유`가 보이도록 설명한다.
5. 그대로 복제하지 않고 더 편리하거나 더 좁고 명확한 기회를 찾는다.
6. 파생 아이디어를 `OPPORTUNITIES.md`에 기록한다.
7. 사업성과 실행 가능성을 평가해 `PRIORITY_ROADMAP.md`에서 순위를 정한다.
8. 실제 프로젝트 착수가 확정되면 `PROJECTS.md` 등록 절차를 따른다.

## 조사 범위

- 특정 산업으로 제한하지 않는다.
- 개인, 기업, 전문직, 개발자, 크리에이터, 학생, 취미, 생활, 업무 등 전 분야를 본다.
- 부동산·건설·소상공인·콘텐츠는 가능한 적용 분야 중 일부일 뿐 우선 제한 조건이 아니다.
- 이미지·영상·문서·데이터·커뮤니케이션·예약·결제·교육·건강·생산성·개발 도구 등 모든 형태를 조사한다.

## 아이디어 탐색 단계의 분석 깊이

아이디어 탐색 단계에서는 아래까지만 확인한다.

- 무엇을 만든 서비스인가
- 누구의 어떤 불편을 해결하는가
- 기존에는 어떤 수작업과 반복 과정으로 해결했는가
- 서비스가 그 과정을 어떤 흐름으로 바꿨는가
- 사용자가 왜 바로 결제하는가
- 셀프서브·자동 제공이 가능한가
- 수익 발생 또는 유료 이용의 근거가 있는가

기술 구조, 구현 방법, API, 데이터 모델, 인프라, 상세 경쟁 분석은 아이디어가 검증 후보로 선정된 뒤 별도 테크니컬 단계에서 진행한다.

## 핵심 아이디어 주제

`불편함 → 반복 작업 → 시간 낭비 → 자동화 가능한 결과물 → 즉시 결제 가능한 가치`

좋은 서비스 후보는 아래 중 하나 이상을 명확히 약속해야 한다.

- 지금 2시간 걸리는 일을 5분으로 줄인다.
- 매주 반복하는 일을 버튼 한 번으로 끝낸다.
- 전문가에게 맡기던 결과물을 즉시 만들어준다.
- 실수를 줄여 돈과 시간이 새는 것을 막는다.

## 기본 원칙

- 새로운 기술 자체보다 사람들이 이미 귀찮아하고 비용을 지불하는 작업을 더 빠르고 편리하게 해결한다.
- 고객 한 명이 늘어도 사람의 업무가 거의 늘지 않는 셀프서브 구조를 우선 검토한다.
- 가입·결제·결과 제공·재구매가 자동화될 수 있는 서비스를 우선한다.
- 매출·사용자 수·운영 인원은 출처로 확인된 내용만 사실로 기록하고, 나머지는 `미확인`으로 표시한다.
- 아이디어 탐색 단계에서는 과도한 상세 분석을 하지 않는다.
- 조사 중인 후보는 `PROJECTS.md`에 등록하지 않는다. 실제 착수가 확정된 경우에만 프로젝트로 승격한다.
