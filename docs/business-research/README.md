# 1인기업 비즈니스 리서치

> 다른 1인기업과 SaaS의 실제 수익 구조를 조사·분석하고, 검증된 성공 구조에서 벤치마킹 요소를 추출해 더 경쟁력 있는 서비스 아이디어를 만들며, 사업성과 실행 가능성을 기준으로 개발 우선순위를 관리한다.

## 운영 흐름

1. 실제로 돈을 버는 1인기업·서비스를 조사한다.
2. 확인된 사실과 추정을 구분해 수익 구조를 분석한다.
3. 고객이 반복해서 겪는 불편·필요·시간 낭비를 찾는다.
4. 반복 작업과 수작업 중 AI·자동화로 줄이거나 없앨 수 있는 지점을 찾는다.
5. 그대로 복제하지 않고, 기존 서비스의 부족한 점과 개선 기회를 찾는다.
6. CozyBuilder가 더 빠르고 편리하게 해결할 수 있는 서비스 아이디어로 전환한다.
7. 사업성과 실행 가능성을 평가해 검증·개발 순위를 정한다.
8. 실제 프로젝트 착수가 확정되면 `PROJECTS.md` 등록 절차를 따른다.

## 문서 구성

- [OPPORTUNITIES.md](OPPORTUNITIES.md): 분석에서 파생된 사업·서비스 아이디어
- [PRIORITY_ROADMAP.md](PRIORITY_ROADMAP.md): 검증 및 개발 우선순위

## 핵심 아이디어 주제

서비스 아이디어는 다음 흐름에서 찾는다.

`불편함 → 반복 작업 → 시간 낭비 → 자동화 가능한 결과물 → 즉시 결제 가능한 가치`

우선적으로 찾을 문제는 다음과 같다.

- 사람들이 반복해서 불평하거나 필요로 하는 문제
- 엑셀·카톡·이메일·복사/붙여넣기 등으로 반복 처리하는 작업
- 시간이 오래 걸리고 자주 반복되는 수작업
- 실수하면 돈·시간·신뢰를 잃는 업무
- 전문가나 외주에 이미 비용을 지급하는 결과물
- AI·자동화로 즉시 또는 반자동 처리할 수 있는 작업
- 상담 없이 사용자가 가치를 이해하고 바로 결제할 수 있는 문제

좋은 서비스 후보는 아래 중 하나 이상을 명확히 약속해야 한다.

- 지금 2시간 걸리는 일을 5분으로 줄인다.
- 매주 반복하는 일을 버튼 한 번으로 끝낸다.
- 전문가에게 맡기던 결과물을 즉시 만들어준다.
- 실수를 줄여 돈과 시간이 새는 것을 막는다.

## 기본 원칙

- 아이디어보다 실제 수익 구조와 고객 문제 분석을 먼저 한다.
- 매출·가격·고객·운영 방식은 출처로 확인된 내용만 사실로 기록한다.
- 확인할 수 없는 비용·매출·전환율은 `추정`으로 표시한다.
- 벤치마킹은 구조를 배우는 것이며, 브랜드·콘텐츠·기능을 그대로 복제하지 않는다.
- 새로운 기술 자체보다 사람들이 이미 귀찮아하고 비용을 지불하는 작업을 더 빠르고 편리하게 해결한다.
- 최신 AI나 기존 SaaS로 이미 해결 가능한 문제인지 먼저 확인한다.
- 고객 한 명이 늘어도 사람의 업무가 거의 늘지 않는 셀프서브 구조를 우선 검토한다.
- 가입·결제·결과 제공·재구매가 자동화될 수 있는 서비스를 우선한다.
- 개발 전 가장 작은 비용으로 수요와 결제 의사를 검증한다.
- 조사 중인 후보는 `PROJECTS.md`에 등록하지 않는다. 실제 착수가 확정된 경우에만 프로젝트로 승격한다.
