# 4차 수집 — 사례 19~28

> 아이디어 구조를 파악하기 위한 상용 서비스 간단 분석. 기술 구현과 상세 경쟁 분석은 검증 후보 선정 후 진행한다.

## 19. Testimonial

- 서비스: 고객의 텍스트·영상 후기, NPS, 사례 인터뷰와 브랜드 언급을 수집·정리·게시하는 서비스
- 운영 형태: 현재 운영 인원 미확인
- 아이디어 구조: 사업자는 만족한 고객이 있어도 후기 요청을 미루거나, 이메일·SNS·리뷰 사이트에 흩어진 칭찬을 판매에 활용하지 못한다. Testimonial은 후기 수집 전용 링크와 자동 요청 흐름을 제공하고, 들어온 후기를 한곳에서 선별해 웹사이트 위젯으로 바로 게시하도록 만들었다.
- 기존 방식: 고객에게 일일이 후기 요청 → 영상 파일과 문장을 따로 수집 → 좋은 부분을 편집 → 개발자에게 홈페이지 게시 요청
- 바꾼 방식: 수집 페이지 공유 → 고객이 글·영상 제출 → 자동 정리·전사 → 승인한 후기를 Wall of Love와 임베드 위젯으로 즉시 공개
- 바로 결제하는 이유: 새로운 고객의 신뢰와 구매 전환에 직접 쓰이는 자료를 별도 개발·편집 없이 만들 수 있음
- 자동 제공 구조: 가입 → 수집 페이지 생성 → 후기 접수·가져오기 → 분류·승인 → 사이트 임베드
- 확인 근거: https://testimonial.to/
- 파생 아이디어: 고객이 이미 만들어 놓은 칭찬·성과·사용 결과를 자동 수집해 판매 가능한 신뢰 자산으로 전환

## 20. Dub

- 서비스: 짧은 링크, 전환 추적, 제휴·추천 프로그램을 통합한 마케팅 링크 플랫폼
- 운영 형태: 현재 운영 인원 미확인
- 아이디어 구조: 마케터는 링크 단축, UTM 관리, 클릭 분석, 매출 귀속, 제휴 파트너 정산을 서로 다른 도구에서 처리한다. Dub은 모든 고객 유입의 시작점인 링크를 중심으로 클릭부터 구매와 파트너 보상까지 한 흐름으로 연결했다.
- 기존 방식: 링크 단축 도구 → 분석 도구 → 결제 데이터 → 제휴 관리 스프레드시트를 따로 운영
- 바꾼 방식: 브랜드 링크 생성 → 클릭·리드·매출 자동 연결 → 어떤 링크와 파트너가 실제 수익을 만들었는지 한 화면에서 확인
- 바로 결제하는 이유: 단순 클릭 수가 아니라 광고·콘텐츠·파트너 활동이 만든 실제 매출을 확인하고 운영할 수 있음
- 자동 제공 구조: 도메인·결제 시스템 연결 → 링크 생성 → 전환 자동 기록 → 파트너별 수익·보상 관리
- 확인 근거: https://dub.co/
- 파생 아이디어: 업무의 출발점이 되는 작은 식별자 하나를 중심으로 뒤의 성과·정산·추적까지 통합

## 21. Typefully

- 서비스: 여러 소셜미디어의 글 작성, 미리보기, 협업, 예약 게시와 성과 분석
- 운영 형태: 현재 운영 인원 미확인
- 아이디어 구조: 소셜 콘텐츠 작성자는 플랫폼마다 좁은 작성창에서 글을 쓰고, 스레드 모양을 상상하며, 게시 시간을 따로 관리한다. Typefully는 글쓰기에 집중하는 편집기와 실제 게시 모습 미리보기, 콘텐츠 달력과 예약 기능을 하나로 묶었다.
- 기존 방식: 메모 앱에서 초안 작성 → 플랫폼에 복사 → 줄바꿈·스레드 수정 → 시간 맞춰 수동 게시 → 분석 화면 재확인
- 바꾼 방식: 한 편집기에서 작성·검토 → 플랫폼별 모습 확인 → 팀 승인 → 여러 채널에 예약 발행
- 바로 결제하는 이유: 매일 콘텐츠를 만드는 개인과 팀이 게시 실수와 반복 복사를 줄이고 일정한 발행 습관을 유지할 수 있음
- 자동 제공 구조: 계정 연결 → 콘텐츠 작성·미리보기 → 예약 → 자동 게시 → 성과 분석
- 확인 근거: https://typefully.com/
- 파생 아이디어: 결과물이 실제 배포될 환경을 미리 보여주고 작성·승인·배포를 한 작업 공간으로 통합

## 22. Readwise Reader

- 서비스: 웹문서, 뉴스레터, RSS, PDF, EPUB, 유튜브 자막과 소셜 스레드를 한곳에서 읽고 표시하는 통합 리더
- 운영 형태: 현재 운영 인원 미확인
- 아이디어 구조: 사람들은 읽을 자료를 브라우저 북마크, 이메일, PDF 폴더, RSS 앱, 유튜브에 흩어 놓고 다시 찾지 못한다. Reader는 콘텐츠 형식이 달라도 하나의 읽기 대기함으로 모으고, 하이라이트와 분류를 동일한 방식으로 처리한다.
- 기존 방식: 각 앱에서 저장 → 읽을 목록이 여러 곳에 쌓임 → 중요한 문장을 별도 노트로 복사 → 저장만 하고 소비하지 못함
- 바꾼 방식: 모든 자료를 하나의 받은편지함에 저장 → 우선순위별 정리 → 읽기·하이라이트 → 지식 관리 흐름으로 연결
- 바로 결제하는 이유: 여러 읽기 앱을 대체하고, 이미 저장한 자료를 실제로 읽고 활용할 확률을 높임
- 자동 제공 구조: 브라우저·이메일·RSS·파일 연동 → 콘텐츠 수집 → 통합 읽기 → 하이라이트 동기화
- 확인 근거: https://readwise.io/read
- 파생 아이디어: 형식과 출처가 다른 자료를 하나의 처리 대기열과 동일한 작업 방식으로 통합

## 23. Scribe

- 서비스: 사용자가 화면에서 업무를 수행하면 단계별 매뉴얼과 SOP를 자동 생성하는 문서화 도구
- 운영 형태: 현재는 조직형 서비스이며 운영 인원 미확인
- 아이디어 구조: 업무 담당자는 자신이 아는 절차를 다른 사람에게 설명하기 위해 화면을 캡처하고 화살표를 넣고 문장을 쓰는 데 많은 시간을 쓴다. Scribe는 실제 작업 과정을 기록해 클릭 위치, 화면 이미지와 단계 설명을 자동 문서로 만든다.
- 기존 방식: 업무 재현 → 단계마다 캡처 → 이미지 편집 → 순서와 설명 작성 → 변경될 때 다시 제작
- 바꾼 방식: 녹화 시작 → 평소처럼 작업 → 자동으로 단계별 문서 생성 → 필요한 부분만 수정·공유
- 바로 결제하는 이유: 교육·인수인계·고객 안내에 반복 사용되는 문서를 훨씬 빠르게 만들고 설명 실수를 줄임
- 자동 제공 구조: 작업 캡처 → 화면·행동 분석 → SOP 자동 생성 → 링크·문서로 배포
- 확인 근거: https://scribe.com/
- 파생 아이디어: 결과물을 직접 작성하게 하지 않고 사용자의 실제 행동을 관찰해 문서·기록·보고서로 변환

## 24. PDF.ai

- 서비스: PDF에 질문하고 내용을 요약·검색하며, PDF 파싱·추출·분할 기능을 API로 제공
- 운영 형태: 현재 운영 인원 미확인
- 아이디어 구조: 긴 계약서·논문·설명서에서 답을 찾으려면 전체를 읽거나 검색어를 정확히 알아야 한다. PDF.ai는 문서를 업로드한 뒤 자연어 질문으로 필요한 정보와 근거 위치를 찾게 한다.
- 기존 방식: PDF 전체 읽기 → 키워드 검색 반복 → 관련 페이지 복사 → 직접 요약·비교
- 바꾼 방식: PDF 업로드 → 문서와 대화 → 질문별 답변·요약·정보 추출 → 필요 시 API로 업무 시스템에 연결
- 바로 결제하는 이유: 읽어야 할 문서가 많을수록 검색·요약 시간을 즉시 줄이고 전문 지식 접근을 쉽게 만듦
- 자동 제공 구조: 파일 업로드 → 문서 파싱 → 자연어 질의 → 답변·추출 결과 제공
- 확인 근거: https://pdf.ai/
- 파생 아이디어: 사람들이 반복해서 읽는 특정 문서 유형을 질문·검토·추출 중심의 전문 도구로 전환

## 25. Cleanup.pictures

- 서비스: 사진에서 사람, 물체, 글자, 얼룩과 결함을 브러시로 지우는 AI 이미지 보정 도구
- 운영 형태: 현재 운영 인원 미확인
- 아이디어 구조: 사진의 작은 방해 요소 하나를 지우기 위해 포토샵을 배우거나 전문가에게 수정 요청해야 했다. Cleanup.pictures는 사용자가 지울 부분을 칠하기만 하면 AI가 뒤 배경을 복원하도록 작업을 한 단계로 줄였다.
- 기존 방식: 전문 편집 프로그램 실행 → 복제 도구·마스크 사용 → 경계와 배경 수동 보정 → 반복 수정
- 바꾼 방식: 사진 업로드 → 제거할 영역을 브러시로 표시 → AI가 몇 초 안에 배경 재구성 → 다운로드
- 바로 결제하는 이유: 전문 기술 없이도 판매 사진·프로필·여행 사진에서 눈에 띄는 문제를 즉시 해결
- 자동 제공 구조: 이미지 업로드 → 영역 표시 → AI 인페인팅 → 결과 미리보기·다운로드
- 확인 근거: https://cleanup.pictures/
- 파생 아이디어: 복잡한 전문 프로그램의 수십 기능 중 사람들이 자주 돈을 내는 한 가지 수정 작업만 분리

## 26. Reclaim

- 서비스: 일정, 업무, 습관, 집중 시간과 미팅을 우선순위에 따라 자동 배치하는 AI 캘린더
- 운영 형태: 현재 운영 인원 미확인
- 아이디어 구조: 할 일 앱에 업무를 적어도 실제 달력에 시간을 배정하지 않으면 실행되지 않는다. 일정이 바뀔 때마다 사용자가 직접 업무를 옮겨야 한다. Reclaim은 우선순위와 마감일을 기준으로 빈 시간을 찾아 업무를 배치하고, 충돌이 생기면 자동 재조정한다.
- 기존 방식: 할 일 목록 확인 → 빈 시간 검색 → 달력에 수동 배치 → 회의가 생길 때마다 이동 → 여러 캘린더 충돌 확인
- 바꾼 방식: 업무·습관·집중 목표 등록 → AI가 가능한 시간에 자동 배치 → 일정 변경 시 유연하게 재배치
- 바로 결제하는 이유: 계획을 세우는 시간뿐 아니라 중요한 일을 놓치거나 회의에 밀리는 손실을 반복적으로 줄임
- 자동 제공 구조: 캘린더·업무 도구 연결 → 우선순위 분석 → 일정 자동 생성·재배치 → 사용 시간 분석
- 확인 근거: https://reclaim.ai/
- 파생 아이디어: 목록에만 존재하는 할 일을 실제 실행 가능한 시간·자원 슬롯에 자동 배정

## 27. Bardeen

- 서비스: 웹 검색·스크래핑, 리드 정보 보강, 분류와 스프레드시트·CRM 전송을 자동화하는 작업 도구
- 운영 형태: 현재 조직형 서비스이며 운영 인원 미확인
- 아이디어 구조: 영업·채용·조사 담당자는 여러 사이트를 검색해 사람과 회사 정보를 복사하고, 연락처를 찾고, 조건에 맞는지 판단한 뒤 표에 옮긴다. Bardeen은 이 연속 작업을 템플릿과 AI 에이전트로 묶었다.
- 기존 방식: 검색 → 페이지 방문 → 데이터 복사 → 연락처 확인 → 적합도 판단 → Sheets·CRM 입력
- 바꾼 방식: 원하는 대상 조건 설정 → 웹에서 자동 수집 → 연락처 보강·AI 분류 → 지정 도구로 자동 전송
- 바로 결제하는 이유: 매주 수십 시간 소비되는 조사·입력 작업을 줄이고 더 많은 후보를 같은 인원으로 처리
- 자동 제공 구조: 검색 조건·스크래퍼 선택 → 데이터 수집 → 검증·분류 → 외부 도구 동기화
- 확인 근거: https://www.bardeen.ai/
- 파생 아이디어: 사람이 여러 화면을 옮겨 다니며 수행하는 조사-판단-입력의 연속 과정을 하나의 자동 파이프라인으로 판매

## 28. Pulsetic

- 서비스: 웹사이트, API, SSL, 도메인과 예약 작업의 장애를 감시하고 알림·상태 페이지를 제공
- 운영 형태: 현재 운영 인원 미확인
- 아이디어 구조: 사이트 운영자는 장애가 발생해도 고객 문의나 매출 감소가 시작된 후에야 알아차리는 경우가 많다. Pulsetic은 전 세계 위치에서 서비스를 반복 확인하고 문제가 생기면 전화·문자·이메일·협업 도구로 즉시 알린다.
- 기존 방식: 운영자가 직접 접속 확인 → 고객 신고 대기 → 장애 원인 확인 → 고객에게 별도 공지 → 가동률 보고서 수동 작성
- 바꾼 방식: 주소와 검사 조건 등록 → 시스템이 24시간 자동 확인 → 장애 즉시 알림 → 상태 페이지와 이력 보고 자동 제공
- 바로 결제하는 이유: 장애로 인한 매출·신뢰 손실을 줄이고 사람이 밤낮으로 확인할 필요를 없앰
