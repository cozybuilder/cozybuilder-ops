## 49. Cal.com

- 서비스: 개인·팀·조직용 일정 예약과 라우팅·결제·알림 자동화
- 운영 형태: 오픈소스 기반 상용 서비스. 현재 팀 규모 미확인
- 아이디어 구조: 미팅을 잡을 때 이메일로 가능한 시간을 주고받고, 시간대를 계산하고, 팀 내 담당자를 정하는 반복 작업을 예약 링크와 라우팅 규칙으로 자동화했다.
- 기존 방식: 가능한 시간 확인 → 이메일 왕복 → 담당자 배정 → 캘린더 등록 → 알림 발송
- 바꾼 방식: 예약 링크 공유 → 참석자가 시간 선택 → 조건에 맞는 담당자 자동 배정 → 캘린더·화상회의·결제·알림 자동 생성
- 바로 결제하는 이유: 영업·채용·상담처럼 예약이 많은 팀은 조율 시간과 일정 충돌을 반복적으로 줄일 수 있음
- 가격: 개인 무료. 연 결제 기준 Teams $12/사용자/월, Organizations $28/사용자/월, Enterprise 별도 견적. 유료 플랜 14일 체험
- 자동 제공 구조: 캘린더·도구 연결 → 이벤트와 라우팅 설정 → 예약·결제·알림 자동 처리
- 확인 근거: https://cal.com/pricing
- 파생 아이디어: 사람이 조건을 확인해 담당자를 배정하던 예약·신청 업무를 규칙 기반 자동 라우팅으로 전환

## 50. Featurebase

- 서비스: 고객지원 받은편지함, AI 답변, 피드백, 로드맵, 변경사항과 도움말 센터 통합
- 운영 형태: 상용 SaaS. 현재 팀 규모 미확인
- 아이디어 구조: 고객 문의, 기능 요청, 로드맵, 공지와 도움말이 여러 도구에 흩어지면 고객 목소리가 제품 결정과 지원 업무로 연결되지 않는다. Featurebase는 지원과 제품 피드백을 같은 고객 데이터 위에서 묶었다.
- 기존 방식: 채팅·이메일 문의 처리 → 기능 요청 별도 수집 → 로드맵 수동 정리 → 공지·도움말 다른 도구에서 작성
- 바꾼 방식: 문의와 피드백 통합 수집 → AI 답변·분류 → 기능 요청·로드맵 연결 → 변경사항과 도움말까지 같은 공간에서 배포
- 바로 결제하는 이유: 여러 고객지원·피드백 도구 구독과 데이터 이동을 줄이고 고객 요구를 제품 개선으로 바로 연결할 수 있음
- 가격: 무료 플랜. 연 결제 기준 Growth $29/좌석/월, Professional $59/좌석/월, Enterprise $99/좌석/월. AI 해결 건당 $0.49 표시
- 자동 제공 구조: 고객 채널 연결 → 문의·피드백 자동 수집 → AI 처리·워크플로 → 로드맵·공지·도움말 연결
- 확인 근거: https://www.featurebase.app/pricing
- 파생 아이디어: 서로 다른 부서가 처리하던 고객 신호를 하나의 고객 데이터와 후속 실행 흐름으로 통합

## 51. Documenso

- 서비스: 전자서명, 문서 템플릿, 팀 서명 흐름과 임베디드 서명 API
- 운영 형태: 오픈소스 기반 상용 서비스. 현재 팀 규모 미확인
- 아이디어 구조: 계약서를 이메일로 보내고 서명 위치를 설명하며, 회신 파일을 저장하고 미서명자를 재촉하는 과정을 서명 링크와 자동 상태 추적으로 바꿨다.
- 기존 방식: 문서 작성 → 이메일 첨부 → 서명 위치 설명 → 서명 파일 회수 → 저장·상태 확인
- 바꾼 방식: 문서 업로드·템플릿 선택 → 수신자와 필드 지정 → 서명 링크 발송 → 완료 상태와 서명본 자동 보관
- 바로 결제하는 이유: 계약·동의서가 반복되는 개인과 팀이 서명 누락, 문서 버전 혼선과 추적 시간을 줄일 수 있음
- 가격: 무료 월 5문서. 연 결제 기준 Individual $25/월, Teams $40/월(5명 포함), Platform $250/월, Enterprise 별도 견적
- 자동 제공 구조: 문서·수신자 설정 → 서명 요청 자동 발송 → 진행 상태·완료 문서 자동 기록
- 확인 근거: https://documenso.com/pricing
- 파생 아이디어: 이메일 첨부로 왕복하는 승인·동의 업무를 상태 추적 가능한 링크형 워크플로로 전환

## 52. Frill

- 서비스: 고객 아이디어 수집, 투표, 로드맵, 공지와 설문 통합
- 운영 형태: 상용 SaaS. 현재 팀 규모 미확인
- 아이디어 구조: 기능 요청이 이메일·채팅·회의에 흩어지고, 같은 요구가 반복되며, 고객은 요청이 어떻게 처리되는지 모른다. Frill은 공개·비공개 아이디어 보드와 로드맵·공지·설문을 연결했다.
- 기존 방식: 요청 복사·정리 → 중복 확인 → 내부 우선순위 회의 → 고객에게 개별 진행 상황 안내
- 바꾼 방식: 고객이 아이디어 제출·투표 → 중복 병합·우선순위화 → 로드맵 이동 → 출시 공지와 설문으로 후속 확인
- 바로 결제하는 이유: 제품팀이 반복되는 요청 정리와 상태 안내를 줄이고 고객 참여를 우선순위 근거로 사용할 수 있음
- 가격: 14일 무료 체험. Startup $25/월, Business $49/월, Growth $149/월, Enterprise $349/월
- 자동 제공 구조: 피드백 보드 설치 → 아이디어·투표 수집 → 로드맵·공지·설문 자동 연결
- 확인 근거: https://frill.co/pricing
- 파생 아이디어: 요청 수집에서 끝나지 않고 우선순위·진행 공개·완료 알림까지 고객 참여 흐름으로 연결

## 53. Nolt

- 서비스: 기능 요청·버그·아이디어 수집 보드와 로드맵
- 운영 형태: 캐나다·스위스 기반 상용 서비스. 현재 팀 규모 미확인
- 아이디어 구조: 작은 팀이 복잡한 제품관리 도구 없이도 고객 요청을 한 게시판에 모으고 투표와 상태로 우선순위를 관리하도록 단순화했다.
- 기존 방식: 이메일·메신저 요청을 스프레드시트에 복사 → 중복 정리 → 상태를 개별 안내
- 바꾼 방식: 고객 보드에 직접 제안 → 투표·댓글·상태 관리 → 로드맵과 외부 업무 도구 연동
- 바로 결제하는 이유: 관리자와 사용자 수에 따라 요금이 늘지 않는 정액제로 고객 피드백 운영 비용을 예측할 수 있음
- 가격: 10일 Pro 체험. 연 결제 기준 Essential $29/월, Pro $69/월, Enterprise 별도 견적. 사용자·콘텐츠·관리자 무제한
- 자동 제공 구조: 보드 개설 → 고객 제안·투표 수집 → 상태·로드맵 관리 → Slack·GitHub·Jira 등 연동
- 확인 근거: https://nolt.io/pricing
- 파생 아이디어: 범용 협업 도구보다 한 가지 외부 참여 업무를 정액제·무제한 구조로 단순화

## 54. Reform

- 서비스: 마케팅·영업용 리드 수집 폼, 조건 분기, 미완료 응답 복구와 CRM 연동
- 운영 형태: 상용 SaaS. 현재 팀 규모 미확인
- 아이디어 구조: 일반 폼은 제출 수집에만 집중하지만 실제 사업자는 좋은 리드를 골라 CRM에 보내고, 중도 이탈한 응답도 활용해야 한다. Reform은 폼을 리드 전환 파이프라인으로 확장했다.
- 기존 방식: 폼 제작 → 제출 자료 확인 → 적합성 수동 판단 → CRM 복사 → 중도 이탈 응답은 폐기
- 바꾼 방식: 다단계 폼·조건 분기 → 이메일 검증·리드 보강 → 미완료 응답 저장 → 조건에 따라 CRM·담당자 자동 전달
- 바로 결제하는 이유: 폼 디자인보다 제출률과 영업 가능성이 높은 리드 확보가 매출과 직접 연결됨
- 가격: 테스트용 Free $0. Basic $15/월, Pro $35/월. 연 결제 시 2개월 무료, Pro 기능 14일 체험
- 자동 제공 구조: 폼 구성·게시 → 응답 수집·검증 → 조건 분류 → CRM·Sheets·Slack 등 자동 전송
- 확인 근거: https://www.reform.app/pricing
- 파생 아이디어: 단순 입력 도구를 결과 수집 이후의 검증·선별·담당자 전달까지 포함한 업무 파이프라인으로 확장

- 바로 결제하는 이유: 장애 중 고객 문의량과 설명 업무를 줄이고 투명한 대응 기록으로 신뢰 손실을 낮춤

- 자동 제공 구조: 서비스·구독자·알림 연동 → 장애 자동·수동 생성 → 상태 페이지와 알림 동시 배포
- 확인 근거: https://www.statuspal.io/pricing
- 파생 아이디어: 내부 사건 하나를 고객·직원·파트너별 필요한 공지 형식으로 동시에 배포하는 상황 대응 서비스

## 이번 배치에서 발견한 패턴

1. 단순 도구보다 `입력 → 검증·분류 → 담당자 전달 → 결과 추적`까지 포함한 파이프라인이 더 높은 가격을 받는다.
2. 고객 문의·기능 요청·공지·도움말처럼 같은 고객 데이터를 쓰는 인접 업무는 하나로 통합할 수 있다.
3. 이메일 첨부·메신저 왕복처럼 상태가 보이지 않는 업무는 추적 가능한 링크와 상태판으로 바꾸면 결제 가치가 생긴다.
4. 정상 상태는 자동으로 숨기고 장애·만료·누락 같은 예외만 알리는 예방형 서비스는 반복 구독과 잘 맞는다.
5. 사용자 수가 많아져도 정액제이거나, 사용량·좌석·처리 건수를 기준으로 가격이 자연스럽게 올라가는 구조가 많다.
