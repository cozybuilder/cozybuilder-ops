# 5차 수집 — 사례 29~38

> 아이디어 구조를 파악하기 위한 상용 서비스 분석. 기술 구현과 상세 경쟁 분석은 검증 후보 선정 후 진행한다.

## 29. Screen Studio

- 서비스: macOS용 화면 녹화·자동 편집 도구
- 운영 형태: 공식 사이트 저작권 표기에 Adam Pietrasiak 이름이 표시되며, 현재 팀 규모는 미확인
- 아이디어 구조: 제품 데모나 강의를 만들려면 녹화 후 확대, 커서 보정, 배경·여백·자막과 세로형 변환을 영상 편집기에서 수작업해야 한다. Screen Studio는 화면 녹화 단계에서 마우스 움직임과 클릭을 분석해 전문 편집 효과를 자동 적용한다.
- 기존 방식: 화면 녹화 → 영상 편집기로 이동 → 클릭 지점 확대 → 커서 움직임 보정 → 배경·자막·출력 비율 수동 조정
- 바꾼 방식: 화면 녹화 → 자동 줌·커서 보정·노이즈 제거·자막 생성 → 플랫폼별 비율로 바로 출력
- 바로 결제하는 이유: 전문 영상 편집 기술 없이도 몇 분 만에 판매·교육·홍보에 쓸 수 있는 완성도 높은 데모 영상을 만들 수 있음
- 자동 제공 구조: 앱 설치·구독 → 화면 녹화 → 자동 편집 → 링크 공유 또는 영상·GIF 출력
- 확인 근거: https://screen.studio/
- 파생 아이디어: 사용자의 작업 과정에서 중요한 행동을 감지해 전문 후처리를 자동 적용하는 결과물 제작 도구

## 30. Compresto

- 서비스: 영상·이미지·PDF·GIF 일괄 압축 및 자동 폴더 감시 앱
- 운영 형태: 현재 운영 인원 미확인
- 아이디어 구조: 파일을 이메일·웹·메신저에 올리기 위해 포맷마다 다른 압축 도구를 찾고, 설정을 바꾸며 하나씩 처리하는 번거로움을 없앴다. 여러 형식을 한 앱에서 처리하고 특정 폴더에 들어온 파일을 자동 압축한다.
- 기존 방식: 파일 용량 확인 → 포맷별 압축 사이트·편집기 실행 → 품질 설정 → 개별 저장 → 업로드 제한에 맞는지 재확인
- 바꾼 방식: 파일을 끌어놓거나 감시 폴더 지정 → 형식에 맞춰 일괄 압축 → 원본 품질을 유지한 작은 파일 자동 생성
- 바로 결제하는 이유: 콘텐츠 제작자와 업무 사용자가 매일 반복하는 용량 줄이기를 빠르게 끝내고 저장 공간·업로드 시간을 줄일 수 있음
- 자동 제공 구조: 앱 구매·설치 → 드래그앤드롭 또는 폴더 감시 → 로컬 자동 압축 → 결과 저장
- 확인 근거: https://compresto.app/
- 파생 아이디어: 여러 전문 도구에 흩어진 동일 목적의 후처리를 하나의 입력 창과 자동 감시 흐름으로 통합

## 31. Leave Me Alone

- 서비스: 여러 이메일 계정의 뉴스레터·광고 메일 일괄 구독 해지와 받은편지함 정리
- 운영 형태: 현재 운영 인원 미확인
- 아이디어 구조: 사용자는 원치 않는 메일이 올 때마다 발신자를 열고 작은 구독 해지 링크를 찾거나 필터를 만들어야 한다. 이 서비스는 연결된 계정에서 구독 목록을 모아 보여주고 선택한 발신자를 일괄 해지한다.
- 기존 방식: 메일 하나씩 열기 → 하단 구독 해지 링크 찾기 → 외부 페이지 이동 → 확인 → 계정별 반복
- 바꾼 방식: 이메일 계정 연결 → 구독 발신자 목록 자동 탐색 → 필요 없는 항목 선택 → 일괄 구독 해지·정리
- 바로 결제하는 이유: 이미 쌓인 수백 개의 구독을 짧은 시간에 정리하고 이후 반복되는 메일 방해를 줄일 수 있음
- 자동 제공 구조: 계정 연결 → 구독 탐색 → 사용자 선택 → 해지 처리와 정리 상태 제공
- 확인 근거: https://leavemealone.com/
- 파생 아이디어: 사용자가 과거에 무심코 만든 다수의 연결·권한·구독을 한곳에서 찾아 정리하는 디지털 청소 서비스

## 32. Podsqueeze

- 서비스: 팟캐스트·영상에서 대본, 쇼노트, 챕터, 제목, 블로그 글과 소셜 콘텐츠 생성
- 운영 형태: 현재 운영 인원 미확인
- 아이디어 구조: 한 편의 오디오를 배포하려면 대본 작성, 핵심 요약, 제목·설명·타임스탬프와 홍보 글을 각각 다시 만들어야 한다. Podsqueeze는 원본 에피소드 하나에서 배포에 필요한 여러 텍스트 결과물을 동시에 생성한다.
- 기존 방식: 오디오 청취 → 받아쓰기 → 핵심 구간 표시 → 쇼노트·블로그·SNS 글을 각각 작성
- 바꾼 방식: 파일 또는 피드 입력 → 자동 전사·요약 → 채널별 콘텐츠 묶음 생성 → 필요한 결과만 수정·배포
- 바로 결제하는 이유: 매회 반복되는 후속 콘텐츠 제작 시간을 줄이고 한 편의 원본을 여러 유입 채널에 재사용할 수 있음
- 자동 제공 구조: 에피소드 업로드·가져오기 → AI 분석 → 여러 형식의 콘텐츠 생성 → 다운로드·편집
- 확인 근거: https://podsqueeze.com/
- 파생 아이디어: 하나의 원본 업무 결과를 이후 필요한 모든 문서·홍보·보고 형식으로 자동 분해해 주는 서비스

## 33. Podscan

- 서비스: 수많은 팟캐스트의 언급·주제·브랜드·인물 모니터링과 검색
- 운영 형태: 현재 운영 인원 미확인
- 아이디어 구조: 기업이나 개인이 자신과 관련된 팟캐스트 언급을 찾으려면 방송을 직접 듣거나 제목·설명만 검색해야 한다. Podscan은 팟캐스트 음성을 전사·색인해 특정 키워드가 실제 대화에서 등장할 때 찾아준다.
- 기존 방식: 팟캐스트 목록 검색 → 관련 있어 보이는 에피소드 선택 → 긴 방송 청취 → 언급 구간 수동 기록
- 바꾼 방식: 키워드·브랜드 등록 → 대규모 에피소드 자동 전사·검색 → 새 언급 발견 시 알림과 문맥 제공
- 바로 결제하는 이유: PR·시장조사·영업 담당자가 놓치기 쉬운 음성 채널의 언급과 잠재 고객 신호를 자동으로 발견할 수 있음
- 자동 제공 구조: 키워드 설정 → 팟캐스트 수집·전사·색인 → 검색·알림 → 결과 활용
- 확인 근거: https://podscan.fm/
- 파생 아이디어: 검색이 어려운 음성·영상·전화·회의 데이터를 지속 수집해 사업에 필요한 특정 신호만 알려주는 모니터링 서비스

## 34. HelpKit

- 서비스: Notion 문서를 고객지원 지식베이스와 도움말 센터로 변환
- 운영 형태: 현재 운영 인원 미확인
- 아이디어 구조: 팀은 이미 Notion에 설명서를 작성하지만 고객용 도움말 사이트를 만들려면 별도 CMS, 디자인, 검색, 도메인과 분석 기능을 다시 구성해야 한다. HelpKit은 Notion을 작성 도구로 유지하고 공개용 지식베이스 기능만 덧붙인다.
- 기존 방식: Notion에서 초안 작성 → 별도 도움말 CMS에 복사 → 메뉴·검색·디자인 구성 → 두 문서 동시 수정
- 바꾼 방식: Notion 페이지 연결 → 고객지원 사이트 자동 생성 → Notion에서 수정하면 공개 문서도 자동 갱신
- 바로 결제하는 이유: 새로운 문서 도구를 도입하거나 개발하지 않고 기존 내부 문서를 즉시 고객지원 자산으로 사용할 수 있음
- 자동 제공 구조: Notion 연결 → 구조·디자인 설정 → 도메인 게시 → 변경 내용 자동 반영
- 확인 근거: https://www.helpkit.so/
- 파생 아이디어: 사용자가 이미 관리하는 내부 자료를 입력 원본으로 유지하고 외부 고객용 형태와 기능만 자동 추가

## 35. Potion

- 서비스: Notion 페이지를 맞춤형 웹사이트로 변환
- 운영 형태: 현재 운영 인원 미확인
- 아이디어 구조: 개인과 작은 팀은 Notion에서 내용을 쉽게 작성하지만, 공식 사이트로 공개하려면 디자인·도메인·SEO·탐색 구조를 따로 만들어야 한다. Potion은 Notion의 작성 편의성을 유지하면서 공개 사이트에 필요한 기능을 붙인다.
- 기존 방식: Notion에서 내용 작성 → 웹빌더나 개발 코드에 복사 → 디자인·메타태그·도메인 설정 → 수정 시 재반영
- 바꾼 방식: Notion 페이지 선택 → 테마·도메인 설정 → 웹사이트 자동 생성 → Notion 수정 내용 자동 동기화
- 바로 결제하는 이유: 개발과 CMS 학습 없이도 이미 작성한 자료를 브랜드 사이트·포트폴리오·문서 사이트로 즉시 공개할 수 있음
- 자동 제공 구조: Notion 연결 → 사이트 설정 → 자동 배포·동기화
- 확인 근거: https://potion.so/
- 파생 아이디어: 익숙한 범용 도구를 백오피스로 쓰고 특정 판매·공개 목적에 맞는 프런트 화면만 자동 생성

## 36. AudioPen

- 서비스: 음성 메모를 구조화된 글·이메일·노트·게시물로 변환
- 운영 형태: 현재 운영 인원 미확인
- 아이디어 구조: 생각을 말하는 것은 빠르지만 음성 메모는 장황하고 다시 듣기 어려워 실제 문서로 활용되지 못한다. AudioPen은 말의 핵심을 유지하면서 군더더기를 제거하고 사용 목적과 문체에 맞는 완성된 글로 정리한다.
- 기존 방식: 음성 메모 녹음 → 다시 듣기 → 직접 받아쓰기 → 문장 순서와 표현 수정 → 원하는 형식으로 재작성
- 바꾼 방식: 자유롭게 말하기 → 자동 전사·정리 → 선택한 문체와 형식의 글 생성 → 복사·공유
- 바로 결제하는 이유: 글쓰기 전에 머릿속 생각을 정리하는 부담을 줄이고 이동 중에도 빠르게 완성 문서를 만들 수 있음
- 자동 제공 구조: 음성 입력 → 전사·구조화 → 스타일 적용 → 완성 텍스트 제공
- 확인 근거: https://www.audiopen.ai/
- 파생 아이디어: 사용자가 가장 편한 비정형 입력을 받아 업무에 바로 쓸 수 있는 정형 결과물로 변환

## 37. Brandscast

- 서비스: 기업 내부 공지·교육·문화 공유를 위한 비공개 팟캐스트
- 운영 형태: 현재 운영 인원 미확인
- 아이디어 구조: 원격·현장 직원에게 공지를 전달하려면 전사 회의나 긴 이메일을 사용하지만 참석이 어렵거나 읽히지 않는다. Brandscast는 직원별 비공개 팟캐스트 피드를 만들어 기존 팟캐스트 앱에서 원하는 시간에 듣게 하고 개인별 청취 여부까지 확인한다.
- 기존 방식: 전사 회의 일정 조율 → 발표 → 불참자에게 녹화·자료 전달 또는 긴 이메일 발송 → 실제 확인 여부 불명
- 바꾼 방식: 짧은 음성 업로드 → 직원별 비공개 피드 배포 → 익숙한 앱에서 비동기 청취 → 개인별 참여 분석
- 바로 결제하는 이유: 회의 시간을 줄이면서 현장·원격 직원을 포함한 전체 조직에 공지를 전달하고 실제 청취 여부를 확인할 수 있음
- 자동 제공 구조: 오디오 업로드 → 직원 초대·비공개 피드 생성 → 팟캐스트 앱 배포 → 청취 분석
- 확인 근거: https://brandscast.com/
- 파생 아이디어: 읽히지 않는 내부 공지와 교육을 사용자가 일상적으로 소비하는 매체로 바꾸고 이행 여부까지 추적

## 38. Cronitor

- 서비스: 예약 작업, 백그라운드 작업, 웹사이트·API와 시스템 신호 모니터링
- 운영 형태: 현재 운영 인원 미확인
- 아이디어 구조: 서버의 예약 작업이나 데이터 백업은 화면에 보이지 않아 실패해도 며칠 동안 발견되지 않을 수 있다. Cronitor는 작업이 정상 실행됐다는 신호를 받고 예정된 시간에 신호가 없거나 오류가 나면 즉시 알린다.
- 기존 방식: 서버 로그 수동 확인 → 작업 결과 파일 검사 → 장애나 고객 신고 이후 실패 인지 → 원인 추적
- 바꾼 방식: 작업에 간단한 모니터링 신호 연결 → 실행·시간·결과 자동 확인 → 실패·미실행·지연 시 담당자에게 알림
- 바로 결제하는 이유: 조용히 실패하는 자동 작업이 매출·백업·정산·고객 서비스에 큰 손해를 만들기 전에 발견할 수 있음
- 자동 제공 구조: 작업·웹·API 연결 → 상태와 신호 지속 수집 → 이상 조건 판단 → Slack·이메일 등으로 알림과 상태 페이지 제공
- 확인 근거: https://cronitor.io/
- 파생 아이디어: 정상일 때는 사람이 보지 않아도 되고, 정해진 행동이나 결과가 발생하지 않을 때만 개입시키는 예외 감시 서비스

## 5차 수집에서 발견한 패턴

1. 전문 후처리를 사용자의 원본 행동 직후 자동 적용한다.
2. 여러 형식에 흩어진 같은 목적의 작업을 하나의 입력 창으로 통합한다.
3. 과거에 쌓인 구독·권한·연결을 찾아 일괄 정리한다.
4. 하나의 원본에서 배포에 필요한 여러 후속 결과물을 동시에 만든다.
5. 검색하기 어려운 음성·비정형 데이터를 지속 수집해 필요한 신호만 알린다.
6. 사용자가 이미 쓰는 도구를 원본 편집기로 유지하고 외부 공개 기능만 추가한다.
7. 사용자가 편한 비정형 입력을 업무용 정형 결과물로 변환한다.
8. 회의·이메일처럼 소비되지 않는 정보를 익숙한 매체로 바꾼다.
9. 정상 상태는 자동으로 지켜보고 예외가 발생할 때만 사람에게 알린다.
