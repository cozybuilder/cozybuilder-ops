# EXTERNAL_INTEGRATION_DIAGNOSTICS — 고비용 외부 연동 장애

> 읽는 시점: OAuth·Google/Apple 로그인·Play/App Store·결제·Supabase/Firebase·DNS·클라우드·외부 API 장애.
> 유래 사건: [PM_INCIDENTS.md](../operations/PM_INCIDENTS.md).

원칙은 `결함 발견 ≠ 근본 원인 확정`, `배포는 마지막 진단 수단`이다.

## 필수 순서

1. ID·키·지문·도메인의 원본 소유 콘솔과 SSOT를 확정한다.
2. 생성지 → 파생 적용 위치 → 런타임 사용처의 전체 계보도를 만든다.
3. 모든 파생 위치를 복사값·명령·byte-level로 대조한다.
4. 로그에서 성공한 마지막 단계와 거부된 첫 단계를 확정한다.
5. 배포 없이 가능한 읽기 전용 검증을 전부 수행한다.
6. 각 가설과 반증 조건을 기록한다. 성공 종단점 전에는 원인 후보로만 표기한다.
7. 한 번의 실험으로 최대한 많은 가설을 분리한다.
8. 사용자 승인 후 변경·배포한다.
9. 중간 성공이 아니라 최종 성공 종단점까지 검증한다.
10. 실패하면 사고 기록과 절차를 갱신한다.

## 배포 전 네 질문

1. 이번 빌드에서 정확히 무엇 하나가 바뀌는가?
2. 결과 A/B/C가 각각 무엇을 확정·배제하는가?
3. 실패 시 다음 분기까지 로그로 판정 가능한가?
4. 같은 결과가 나와도 다시 업로드할 필요가 없는가?

네 질문에 모두 답하지 못하면 업로드하지 않는다. 콘솔 생성·수정·삭제 가능성이 있는 절차를
읽기 전용이라고 표현하지 않는다. 사용자 직접 작업과 대기시간도 실험 비용으로 계산한다.

승인된 제품 계획의 포기·축소·대체는 근거 보고 → 코지 승인 → 문서 반영 후에만 실행한다.
같은 유형의 실수를 반복하면 단순 실수가 아니라 운영 규칙 위반으로 판정한다.
