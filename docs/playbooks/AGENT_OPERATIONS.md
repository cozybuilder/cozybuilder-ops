# AGENT_OPERATIONS — 에이전트 도입·승인 경계

> 읽는 시점: 자율 실행, 예약 작업, 고객·운영 자동화, 에이전트 권한 위임.

## 원칙

- 에이전트는 승인된 목표·범위·접근권·실행권·중단 조건 안에서만 행동한다.
- 편의를 이유로 API·SaaS·서버 비용을 무제한 늘리지 않는다.
- 권한 위임이 문서화되지 않은 경우 기존 작업별 승인 루프를 따른다.
- “AI가 알아서 한다”는 표현은 권한 계약을 대신하지 않는다.

## 사람 승인 필수

- 개인정보·고객 데이터
- 결제·환불
- 약관·법률·세무
- 고객 또는 외부 수신자에게 보내는 메시지
- 운영 DB·실사용자 데이터
- 배포·스토어 업로드·외부 공개
- 파괴적 Git 작업

## 절대 금지 포인터

절대 금지와 사전 승인 경계는 [GLOBAL.md §4.2](../../GLOBAL.md)가 단독 소유한다.
에이전트 권한 계약은 그 경계를 완화하거나 예외 처리할 수 없다.

## 안정화 이후 후보 업무

- 고객 문의 응대
- 신규 사용자 온보딩과 사용법 안내
- 구독 전환·리텐션 관리
- 사용 패턴 분석
- 마케팅 후속관리
- 공지·업데이트 안내
- 고객 세그먼트별 메시지 초안

후보는 현재 실행 승인이 아니다. 고객에게 보내는 메시지는 항상 사람 승인 후 발송한다.

## 도입 순서

1. 대상 업무의 고객 가치와 반복성을 확인한다.
2. 판단권·접근권·실행권·책임 기준을 문서화한다.
3. 비용 상한과 중단 기준을 정한다.
4. 민감 지점의 사람 승인 로그를 설계한다.
5. 작은 내부 범위에서 검증한다.
6. 성공지표와 오류 회수 수단이 확인된 뒤 확장한다.

구체적인 자율 개발 권한 위임 계약은 별도 승인 문서가 생기기 전까지 존재하지 않는 것으로 본다.
