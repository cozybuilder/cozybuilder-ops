# GEMINI_USAGE_GUIDE — Gemini 활용 기준

> 역할: Gemini 제품군을 사용할 때의 조건부 라우팅·검증·안전 기준.
> 요금제·기능·한도·계정 화면은 변동값이므로 매 작업에서 공식 문서와 실제 계정을 다시 확인한다.

## 적합한 작업

- Flow 기반 영상 소스 실험
- NotebookLM 자료 정리와 출처 기반 비교
- 공개 웹 Deep Research
- Google Workspace 보조
- 제목·훅·구성의 두 번째 의견

프로젝트 사실의 SSOT는 계속 GitHub다. Gemini나 Drive의 결과를 프로젝트 사실로 바로 승격하지
않는다.

최종 영상은 AI 영상만으로 만들지 않고 실제 사진·앱 화면·실제 경험 내레이션과 조합한다.

## 역할 경계

- 코비는 GitHub 근거·방향·최종 검수를 담당한다.
- 클로는 승인 범위의 구현·검증을 담당한다.
- 클챗은 블로그·SNS·영상 대본의 최종 문장을 담당한다.
- Gemini는 공개 조사·Google 제품·대안 탐색을 보조한다.

조직의 역할 정본은 [ROLES.md](../organization/ROLES.md)다. 이 문서는 Gemini에 적합한 작업만
추가로 설명한다.

## 검증 순서

1. 공식 Google 문서에서 기능·요금·지원 여부를 확인한다.
2. 실제 사용자 계정 화면에서 메뉴·한도를 확인한다.
3. 품질·오류·실전 사례를 조사한다.
4. 작은 테스트를 실행한다.
5. GitHub 사실과 결과물을 독립 검수한다.
6. 효과가 확인된 작업만 반복 업무로 승격한다.

## 금지·주의

- 로그인 내부 데이터·비공개 게시물·private GitHub 접근을 추측하지 않는다.
- 실제 확인하지 않은 계정·게시물·링크를 만들지 않는다.
- 앱에 없는 기능을 홍보 문구에 넣지 않는다.
- AI 결과를 검수 없이 게시하거나 코드에 반영하지 않는다.
- 구독 포함 기능과 별도 API 비용을 혼동하지 않는다.
- 스팸성 댓글·팔로우·대량 발송 자동화에 사용하지 않는다.
