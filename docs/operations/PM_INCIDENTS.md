> 반복 작업 절차는 소유하지 않는다.

## INC-1. CozyRent Google 로그인 진단 지연

- **영향**: 단편 가설을 근본 원인으로 조기 확정하고 반복 배포해 시간·사용자 작업·검증 비용이 증가했다.
- **핵심 원인**:
  - 기준값의 전체 생성·파생·런타임 계보를 먼저 만들지 않음
  - 중간 결함 발견을 최종 원인 확정으로 승격
  - 배포 없는 읽기 전용 검증을 소진하기 전에 새 빌드를 반복
- **교정**: 외부 연동 장애는 기준값 원본 → 계보 → 파생 위치 전수 대조 → 로그 실패 경계 →
  가설·반증 → 승인된 단일 실험 → 성공 종단점 순서로 진단한다.
- **강제 절차**:
  [EXTERNAL_INTEGRATION_DIAGNOSTICS.md](../playbooks/EXTERNAL_INTEGRATION_DIAGNOSTICS.md)
- **원문 사고 기록**:
  [PM_INCIDENTS_V1_2026-07-19.md](../history/PM_INCIDENTS_V1_2026-07-19.md)

## INC-2. QA 전용 환경까지 확대된 미승인 절대 금지선

- **영향**: 문서 재편 중 실사용자 데이터 보호 원칙이 QA 전용 환경까지 절대 금지로
  확대돼, 승인된 실기기 E2E와 QA 자동입력이 문서상 차단됐다.
- **핵심 원인**: 문서 이전(migration)과 신규 정책 수립을 구분하지 않아, 요약 과정에서
  대상 범위(실사용자 vs QA 전용) 조건절이 조용히 빠졌다.
- **교정**: `GLOBAL.md §4.2`를 절대 금지·승인 가능·별도 승인 셋으로 분리하고,
  절대 금지선·승인 경계 변경에는 코지의 명시적 승인 근거를 요구하는 원칙을 명문화했다.
- **원문 사고 기록**:
  [INC-2-unapproved-qa-policy-2026-07-24.md](incidents/INC-2-unapproved-qa-policy-2026-07-24.md)

새 사고는 한 사건당 별도 파일로 기록하고 이 문서에는 요약과 포인터만 추가한다.
