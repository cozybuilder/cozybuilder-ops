# PM_INCIDENTS — PM 판단·운영 사고 기록 (SSOT)

> 소유: 이 문서가 **PM(코비) 판단·운영 실수 사고 기록**의 SSOT다.
> 반복 방지 절차는 [PLAYBOOK.md §P13](../../PLAYBOOK.md)이 소유하고, 여기서는 **사건 사실**만 기록한다.
> 프로젝트별 기술 증거·현재 상태는 각 프로젝트 STATUS.md가 소유한다(전문 복제 금지 — 링크만).
>
> **핵심 원칙(코지 확정)**:
> - "실수는 할 수 있다. 그러나 기록하지 않은 실수와 반복된 실수는 허용하지 않는다."
> - "결함 발견 ≠ 근본 원인 확정"
> - "성공 검증 전에는 원인을 확정형으로 말하지 않는다."
> - "배포는 진단 수단의 마지막 단계이지 첫 단계가 아니다."
>
> 기록 규칙: 사건은 축소·미화 없이 사실대로 남긴다. secret·Client Secret·비공개 키 원문 기록 금지.
> 같은 유형의 실수가 다시 나타나면 단순 실수가 아니라 **운영 규칙 위반**으로 판정한다.

## INC-1. CozyRent Google 로그인 진단 10시간 지연 — 단편 진단·조기 원인 확정·반복 배포

### 발생일
2026-07-18 ~ 2026-07-19 KST

### 영향
- Google 로그인 하나를 해결하기 위해 약 **10시간** 소요.
- Play 내부 테스트 업로드·배포·업데이트 대기를 **여러 번 반복**(v16→v17→v18→v19→v20).
- 매 배포마다 약 **1~2시간의 대기 비용** 발생.
- 사용자(코지)가 콘솔 확인·업로드·실기기 테스트를 반복 수행.
- 기능 개발이 중단되고 신뢰·집중력이 소모됨.
- **최종 원인이 확정되지 않은 상태에서 여러 차례 "근본 원인"이라고 잘못 보고함.**

### 실제 발견된 결함
- Web OAuth Client ID 문자 오타: 영문 소문자 `o` ↔ 숫자 `0`.
- Android OAuth Client SHA-1 문자 오타: 숫자 `8` ↔ 영문 대문자 `B` (첫 옥텟 D8↔DB).

이 두 결함은 **실제 문제**였다. 그러나 각 결함을 발견한 시점에 성공 검증 없이
**"최종 근본 원인"이라고 조기 확정**한 것이 PM 실수였다.
(두 오타를 모두 수정한 뒤에도 v19 standard·v20 bottom 두 경로 모두 [28444]가 지속 —
기술 증거·현재 모순은 [cozyrent/docs/STATUS.md §2.228](https://github.com/cozybuilder/cozyrent/blob/main/docs/STATUS.md) 참조.)

### 코비 PM의 핵심 실수

1. **전체 인증 계보를 처음부터 한 번에 정리하지 않음.**
   Play package·앱 서명 → Android OAuth Client → Web OAuth Client → 앱 webClientId/serverClientId →
   Google Auth Platform → Supabase Provider → 런타임 요청의 연결을 전체 대조하지 않고 **한 항목씩** 확인함.
2. **"실제 결함 발견"과 "최종 근본 원인 확정"을 구분하지 않음.**
   오타 하나를 찾을 때마다 원인 확정으로 보고 → 수정 후 실패하면 새 가설로 이동 → 확정 표현을 여러 차례 번복.
3. **Play 배포 비용을 고려하지 않은 실험 설계.**
   한 번의 배포로 여러 가설을 분리할 수 있었는데 실험을 조각냄. 업로드 전 읽기 전용 대조·로컬 검증을
   충분히 묶지 않고, 매번 다음 가설 하나만 반영해 versionCode와 배포를 반복.
4. **사실보다 추정이 앞섬.** 전파 지연·특정 Credential Manager 경로 문제·백엔드 미반영 등을
   충분한 반증 없이 우선 결론으로 제시.
5. **원래 확정 계획을 임의로 축소하려 함.** Google 로그인은 필수 기반 작업인데
   "지원 문의 또는 여기까지만"처럼 들릴 수 있는 방향을 제안 — 코지 승인 없이 원래 계획을 바꾸려 한 **PM 경계 위반**.
6. **콘솔 조작 안내의 검증 부족.** 입력 단계에서 중복 경고가 날 것이라고 잘못 안내(실제로는 '만들기'를 눌러야
   중복 검증됨). 다행히 중복 오류로 신규 Client는 생성되지 않았으나, **설정 변경 가능성이 있는 행동을
   읽기 전용처럼 안내**함.
7. **사용자 시간을 운영 비용으로 충분히 취급하지 않음.** 기술적으로 가능한 실험인지뿐 아니라
   코지가 직접 기다리고 확인해야 하는 시간까지 작업 비용에 포함하지 않음.

### 잘못된 진행 패턴

```
전체 구조 미확인
→ 결함 1개 발견
→ 근본 원인으로 단정
→ 빌드·Play 업로드
→ 1~2시간 대기
→ 실패
→ 다음 결함 또는 가설 발견
→ 다시 업로드
→ 다시 대기
```

### 앞으로의 강제 재발 방지 규칙

> 절차로서의 소유는 [PLAYBOOK.md §P13](../../PLAYBOOK.md). 아래는 이 사건에서 도출된 원문 규칙이다.

1. 외부 인증·결제·스토어 연동 오류는 먼저 **전체 계보도**를 작성한다.
2. 기준값의 **원본 소유자를 먼저 확정**하고 파생 적용 위치를 나열한다.
3. 이미지 육안 대조보다 **복사값·byte-level·명령 실측**을 우선한다.
4. 발견된 결함은 **"원인 후보"로 기록**하고, 성공 검증 전 "근본 원인" 표현을 **금지**한다.
5. 배포가 오래 걸리는 작업은 업로드 전에 **가능한 모든 읽기 전용 검증을 한 번에** 수행한다.
6. **한 번의 배포로 분리할 수 있는 가설과 로그를 미리 설계**한다.
7. 다음 배포 전에 아래 질문에 **모두 답하지 못하면 업로드하지 않는다**:
   - 이번 빌드에서 정확히 무엇 하나가 바뀌는가?
   - 결과 A/B/C 각각 무엇을 확정·배제하는가?
   - 실패 시 다음 분기까지 로그로 판정 가능한가?
   - 동일 결과가 나왔을 때 또 업로드가 필요한가?
8. 콘솔 생성·수정·삭제 **가능성**이 있는 절차는 "읽기 전용"이라고 표현하지 않는다.
9. 원래 승인된 제품 계획을 코비가 임의로 포기·축소·대체하지 않는다.
10. 방향 변경은 **근거 보고 → 코지 승인 → 문서 반영** 후에만 실행한다.
11. **사용자 직접 작업과 대기시간도 명시적인 비용**으로 계산한다.
12. 같은 유형의 실수가 다시 나타나면 단순 실수가 아니라 **운영 규칙 위반**으로 판정한다.

### 최종 결과 (2026-07-19 보강 — 성공 검증 후 확정)

- **최종 원인**: 실제 GCP Web Client ID의 `q45o88613`은 **영문 소문자 `o`(0x6f)** 였다.
  **콘솔 화면 이미지 확대 판독**에서 `o`를 숫자 `0`(0x30)으로 오독해 "교정"으로 정상값을 오염 —
  v19·v20은 존재하지 않는 0버전 serverClientId로 요청해 Google이 [28444]/UNREGISTERED로 거부했다.
  v21에서 코지가 콘솔에서 **직접 복사한 텍스트 원본(o)** 으로 원복(cozyrent commit cc3f33a)하자
  Google credential → idToken → Supabase → 세션 생성·복원까지 **즉시 성공**(CozyRent STATUS §2.230).
- SHA-1 D8↔DB 오독(같은 이미지 판독 유형)도 실제 결함이었으나 그것만으로는 미해소였다 —
  **두 개의 이미지 오독이 겹쳐** 진단을 10시간 지연시켰다.
- **추가 확인된 실수**: ⑧ 이미지 기반 식별자 판독을 사실값으로 승격(오독을 "byte-level 확정"으로 포장)
  ⑨ 성공 검증 전 원인을 두 차례 조기 확정(o↔0 → SHA D8↔DB) ⑩ 문서·코드·콘솔을 매 단계 원문(텍스트 복사)으로
  대조하지 않음 ⑪ 클로 완료보고 검수·코지 승인 전에 다음 지시서를 발행(지시 파이프라이닝 — PM 절차 위반).

### 재발 방지 규칙 보강 (2026-07-19 · 13~17)

13. **Client ID·SHA·키·도메인은 이미지/OCR 입력 금지** — 텍스트 직접 복사만 허용.
14. 설정값 확정은 **원본 문자열·길이·hex/hash 비교** 필수(육안·이미지 확대 판독은 확정 근거가 아니다).
15. 값 검증은 **소스 → 번들 → AAB → Play 설치본 → 런타임** 계보를 원문으로 확인한다.
16. **성공 종단점 확인 전 "근본 원인" 표현 금지**(발견 결함은 "원인 후보"로만).
17. 지시 루프 고정: **완료보고 검수 → 코지 설명 → 승인 → 다음 지시 1개** — 진행 중 작업 완료 전 추가 지시 금지.
